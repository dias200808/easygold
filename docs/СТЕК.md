# Стек и инструменты

Решения приняты окончательно, отклонённые варианты указаны, чтобы к ним не возвращаться.
Там, где аналитики предложили разные варианты одного и того же, конфликт разрешён здесь (раздел «Спорные места»).

## 1. Ядро

| Что | Выбор | Почему именно так |
|---|---|---|
| Фреймворк | **Next.js 16, App Router, TypeScript** | Задан ТЗ. RSC даёт минимум клиентского JS на главной и странице игры, `generateMetadata`/`sitemap.ts`/`robots.ts` из коробки — без SEO-библиотек. Отклонён Pages Router (больше JS в бандле), Astro + отдельный бэкенд (два рантайма на одного разработчика) |
| База | **PostgreSQL 17** + расширения `pgcrypto`, `citext` | `citext` для регистронезависимого email (Prisma умеет `@db.Citext`; выраженный индекс по `lower(email)` пришлось бы держать в raw-SQL). Отклонён MySQL: нет частичных индексов, слабее `SKIP LOCKED` |
| ORM | **Prisma 6** + `$queryRaw` внутри `$transaction` | Задан ТЗ. Важная деталь: Prisma не умеет `SELECT ... FOR UPDATE` декларативно — блокировка строки заказа при обработке вебхука делается сырым запросом внутри транзакции |
| Стилизация | **Tailwind CSS 4** (`@theme` в CSS, без JS-конфига) | Задан ТЗ. Отклонены CSS Modules (нет токенов и утилит), styled-components/emotion (runtime CSS-in-JS плохо совместим с RSC) |
| Деньги | **собственный `lib/money.ts` на BigInt в тиынах** | Целые минорные единицы исключают ошибки округления скидок и расхождения при сверке с выпиской. Отклонён Prisma `Decimal` (арифметика всё равно требует decimal.js, неудобная сериализация), `dinero.js` (лишний слой) |
| Валидация | **zod** | Один инструмент на три задачи: недоверенное тело вебхука, `env` на старте, схемы форм совместно с react-hook-form. Отклонён yup (слабее выводит типы) |
| ID | `cuid2` для первичных ключей, **`nanoid` с алфавитом A-Z0-9** для `public_token`, `order_number` и `external_id` | `external_id` уходит во внешнюю платёжную систему, где вероятны ограничения длины и алфавита — дефисы и путающиеся символы исключаются заранее. Автоинкремент отклонён: раскрывает объём заказов |

## 2. Фоновые задачи и планировщик

**Выбор: собственная таблица `jobs` + воркер (~250 строк в `lib/queue`).**

ТЗ §20 прямо это допускает, и в нашем случае это лучше готовых пакетов по трём причинам:
- Нужны **точные** паузы 10 / 30 / 90 с из §11.2 — у готовых очередей backoff задаётся своей формулой.
- Нужен **транзакционный outbox**: задача выдачи не должна появиться, если смена статуса откатилась. `enqueue` — это `INSERT` в той же транзакции Prisma.
- Схема остаётся целиком под управлением Prisma-миграций, без второго набора таблиц и своего миграционного механизма.

Отклонены: `pg-boss` (своя схема и свой формат политики ретраев), `graphile-worker` (то же плюс отдельный CLI), BullMQ + Redis (лишний сервис ради 100 заказов в сутки).

Механика: `claim` через `FOR UPDATE SKIP LOCKED`, `run_at` для отложенных, `attempts`/`max_attempts`, dead-letter таблица, reaper зависших задач. Две точки запуска: постоянный процесс `worker` (основная) и эндпоинт `/api/internal/jobs/drain` (резерв и локальная отладка).

## 3. Платежи и фискализация

| Что | Выбор |
|---|---|
| Абстракция | `interface PaymentProvider`: `createPayment` → `redirect \| qr \| deeplink`, `parseWebhook` (только подпись и нормализация), `buildWebhookAck`, `getStatus`, опциональный `refund` |
| Разработка | **`FakeProvider`** + dev-страница `/dev/pay/[externalId]` с кнопками «оплатить / ошибка / оплатить дважды / оплатить после истечения», отправляет настоящий подписанный вебхук |
| Первый реальный | тот из **Kaspi / Freedom Pay**, кто раньше даст доступ. У Freedom Pay документация публичная: `test-api.freedompay.kz`, `init_payment.php`, `get_status3.php`, `revoke.php`, подпись `pg_sig` = MD5 от имени скрипта + все поля по алфавиту + secret, колбэки `pg_result_url` и `pg_check_url` с ретраями каждые 30 мин в течение 2 ч |
| Резерв | Halyk **ePay** — тоже с публичной документацией (OAuth2 `client_credentials`, `postLink`, RSA-подпись) |
| Подпись вебхука | `crypto.timingSafeEqual` (обычное `===` открывает timing-атаку на секрет) |
| Исходящие вызовы | нативный `fetch` + `AbortSignal.timeout` + **`p-retry`** только на сетевых ошибках и 5xx, никогда на 4xx. Отклонён axios + axios-retry |
| Фискализация | `interface FiscalProvider`, реализация `noop` в MVP, **Webkassa** (облачная ККМ с REST API) на этапе 2. Вызывается задачей после перехода в `paid`, сбой не блокирует выдачу, но алертит |

**Важно:** Gateway API Freedom Pay использовать нельзя — он требует сертификации PCI DSS. Нужен только Merchant API с их платёжной страницей.

**Не использовать** сторонние обёртки «Kaspi Pay REST API» (`apipay.kz`, `aipay.kz`, `paybot.kz` и подобные). Они требуют передать им доступ к аккаунту Kaspi Pay, механизм получения данных не раскрывают, официальной аффилиации с Kaspi не заявляют. Это риск блокировки расчётного счёта, а не просто технический риск.

## 4. Поставщики

| Что | Выбор |
|---|---|
| Абстракция | `interface Supplier` с **единым объектом идентификаторов** (`playerId?`, `zoneId?`, `accountLogin?`) вместо позиционных аргументов из §11.1 — иначе типы C и D не выражаются |
| MVP | `ManualSupplier` (плюс поле ввода кода при отметке «Выполнено») |
| Кандидаты на API | **GamesDrop** (`check-game-data` → `gameUserLogin`, цены в KZT, идемпотентность по `transactionId`, вебхуков нет — только polling), **SEAGM Open API** (HMAC-SHA256, `mch_order_id`, есть callback, но документация сама требует polling), **MooGold** (HMAC + Basic, ключи через менеджера) |
| Правило | Вебхук поставщика — **ускоритель, а не источник правды**. `getOrderStatus` с периодическим опросом обязателен всегда |
| Ограничение | Один поставщик на товар из ТЗ противоречит цели 99,5% — в схеме сразу `product_suppliers` с приоритетом, второй канал может быть ручным |

## 5. Фронтенд

| Что | Выбор | Почему |
|---|---|---|
| i18n | **next-intl** | Единственная зрелая библиотека, работающая в Server Components App Router и умеющая статический рендер локализованных страниц (`setRequestLocale`). Отклонены next-i18next (только Pages Router), react-i18next (тянет провайдер в клиент) |
| Формы | **react-hook-form** + zod + `@hookform/resolvers` | Чекаут имеет нетривиальные состояния и зависимость кнопки от пяти условий; zod-схема из `games.id_regex` переиспользуется на сервере — одна правда о валидации |
| Опрос статуса | **swr**, только на `/order/[token]`, через dynamic import | Закрывает то, что ломает самописный `setInterval`: спящая вкладка, дубли запросов, мгновенный refetch при возврате с платёжной страницы. ~4 КБ и не на критическом пути |
| Юр. тексты | **`@next/mdx`** + remark-gfm, файлы в репозитории с полем `version` | Оферта требует истории версий и фиксации «с какой версией согласился покупатель» — git даёт это без админки и миграций |
| JSON-LD | **schema-dts** | Ошибки разметки ловит компилятор, а не Search Console через две недели |
| Изображения | **sharp** + `next/image` | Обязателен для встроенного оптимизатора вне Vercel; AVIF на иконках экономит 40–60% байт над сгибом |
| Шрифты | **системный стек, 0 КБ** | Бюджет 2 с на 3G. Если появится брендовый шрифт — `next/font/local` + сабсет с явным `unicode-range`, включающим **ә ғ қ ң ө ұ ү һ і**: стандартный cyrillic-сабсет казахские глифы не гарантирует, и kk-версия получит подстановку и скачок текста |
| Аналитика | **`@next/third-parties` GoogleAnalytics** (после гидратации) + Яндекс.Метрика `lazyOnload` + **GA4 Measurement Protocol серверно** из вебхука | Пользователь часто не возвращается с платёжной страницы, поэтому клиентское событие покупки теряется. `gtag.js` в `<head>` один съедает бюджет 2 с |

## 6. Инфраструктура

**Хостинг: VPS (2 vCPU / 4 ГБ) + Docker Compose** — сервисы `caddy`, `web`, `worker`, `postgres`, `backup`; воркер с `restart: always`.

Почему не Vercel: §9 требует истечения через 30 минут, автовозврата через 15 минут, начисления через 24 часа, §14.1 — Telegram-бота. На Vercel нет долгоживущих процессов, cron имеет гранулярность 1 минута, и ретрай «через 10 секунд» превращается в «до 70 секунд». Вторую точку входа под Vercel и QStash не тянем.

Площадка выбирается после ответа юриста о локализации персональных данных в РК (см. `ВОПРОСЫ.md`, Q14). Инфраструктура без vendor-lock: только Docker, стандартный PostgreSQL, S3 API — переезд на KZ-провайдера остаётся однодневной задачей.

| Что | Выбор |
|---|---|
| TLS и прокси | **Caddy 2** — автоматический ACME, HSTS, заголовки безопасности, 20 строк конфига. Отклонён nginx + certbot (два компонента, ручное продление) |
| Аутентификация | **`better-auth`** + Prisma adapter: сессии в БД (мгновенная инвалидация при `is_blocked`), плагин TOTP для 2FA админки. Отклонён Auth.js/NextAuth v5 (с Credentials сессии в БД практически не поддерживаются) |
| Пароли | **`@node-rs/argon2`** (argon2id, m=19456, t=2, p=1) — рекомендация OWASP. Отклонены bcryptjs (медленный, лимит 72 байта) и bcrypt на node-gyp (требует компилятора) |
| Rate limiting | **`rate-limiter-flexible`** со стором в PostgreSQL/памяти — без Redis. Отклонён `@upstash/ratelimit` (внешний сервис в критическом пути) |
| Шифрование в БД | **`node:crypto` AES-256-GCM**, формат `v1:iv:tag:ct`, ключ в env, колонка `key_version`. Отклонён `pgcrypto` для этой задачи: ключ уезжает в текст SQL и попадает в логи БД и в Prisma query log |
| Секреты | **`sops` + `age`** — зашифрованный `.env` в git, история изменений, ротация одним коммитом. Отклонён Vault (отдельный сервис и оператор) |

| Логи | **pino** + `pino-roll` с redaction (`authorization`, ключи, подписи) |
| Ошибки | **Sentry** (веб + отдельно воркер), алерт на dead-letter |
| Почта | **Resend** + **react-email** — webhook-события доставки и шаблоны как React-компоненты с теми же i18n-строками. Отклонён nodemailer поверх произвольного SMTP (нет статусов доставки) |
| Telegram | **grammy** — TS-first, webhook-режим, живёт и в воркере, и в route handler |
| Бэкапы | `pg_dump -Fc` + **restic** в S3-совместимое хранилище, `--keep-daily 30`, `restic check`. Плюс снапшоты диска у провайдера как второй слой |
| Мониторинг | **Better Stack Uptime** (free) на `/api/health` и `/api/health/worker`, алерты в Telegram — внешний, чтобы не жить на том же сервере |
| CI/CD | **GitHub Actions** + GHCR + `docker context` через SSH, `prisma migrate deploy`. Docker нужен только на раннере — локальная машина остаётся без него |
| Локальная БД | **Homebrew `postgresql@17`** (Docker и psql на машине не установлены), в CI — `services.postgres` |
| Отладка вебхуков | **`cloudflared` quick tunnel** + скрипт `scripts/mock-webhook.ts`, который подписывает и отправляет тестовый вебхук. Отклонён ngrok free (домен меняется каждый запуск) |
| Тесты | **vitest** + **`@testcontainers/postgresql`** (в CI) / локальный PG. Идемпотентность, `FOR UPDATE`, частичные индексы и гонки невозможно проверить на моках и SQLite |

## 7. Спорные места, разрешённые здесь

| Конфликт | Решение |
|---|---|
| pg-boss / graphile-worker / своя таблица | **Своя таблица** — точные паузы, транзакционный outbox, единые миграции |
| BigInt тиыны / Prisma Decimal / целые тенге | **BigInt тиыны** — точность скидок и сверки |
| Vercel / VPS | **VPS** — постоянный воркер обязателен по §9 |
| Kaspi первым / Freedom первым | **Кто раньше даст доступ**; код пишется на `FakeProvider`, адаптер изолирован в одном файле |
| Подтверждение ника / «Повторите ID» | **«Повторите ID» — основной путь**, подтверждение ника за флагом на связке поставщик+игра |
| Идемпотентность по статусу заказа / по `event_key` | **По `event_key`** (`provider \| external_id \| provider_payment_id \| status \| amount`), уникальный индекс |
| Auth.js / better-auth / своя реализация | **better-auth** — сессии в БД и TOTP из коробки |
