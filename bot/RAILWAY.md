# Развёртывание EasyGold на Railway

Цель: бот работает круглосуточно, ноутбук можно закрыть.

**Важно про деньги.** У Railway нет постоянного бесплатного тарифа — есть стартовый кредит, которого хватает примерно на месяц работы такого бота. Дальше около $5 в месяц. Проверьте актуальные условия на railway.com перед привязкой карты.

**Важно про базу.** Диск контейнера стирается при каждом деплое. Без подключённого тома **все заказы и отзывы исчезнут после первого же обновления.** Шаг 4 пропускать нельзя.

---

## 1. Положить код в GitHub

Railway разворачивает из репозитория.

```bash
cd ~/Desktop/"online game"
git init
git add .
git commit -m "EasyGold"
```

Создайте приватный репозиторий на github.com и запушьте туда.

Проверьте, что `.env` **не попал** в коммит — он в `.gitignore`, но убедитесь:
```bash
git ls-files | grep -i env
```
Должен показать только `.env.example`. Если видите `.env` — токен утёк, немедленно отзовите его у @BotFather через `/revoke` и создайте новый.

## 2. Создать проект

На railway.com: **New Project → Deploy from GitHub repo** → выбрать репозиторий.

Если бот лежит в подпапке `bot`, укажите её: **Settings → Root Directory → `bot`**

## 3. Прописать переменные

**Variables** → добавить по одной:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | ваш токен от BotFather |
| `ADMIN_USERNAME` | `Akhmetbekdi` |
| `REVIEWS_CHANNEL_ID` | `-1004301196583` |
| `DB_PATH` | `/data/bot.db` |
| `MAX_ORDERS_PER_HOUR` | `15` |

`ADMIN_CHAT_ID` не добавляйте — привязка хранится в базе.

## 4. Подключить том для базы — обязательно

**Settings → Volumes → New Volume**, точка монтирования: `/data`

Это то место, куда указывает `DB_PATH`. Без тома база живёт до первого деплоя.

## 5. Остановить локального бота

**Два экземпляра одновременно работать не могут** — Telegram начнёт отдавать ошибку 409 и сообщения будут теряться.

```bash
pkill -f "src/index.js"
```

Только после этого запускайте деплой на Railway.

## 6. Проверить

**Deployments → Logs**, должно появиться:
```
Бот запущен. Оператор: @akhmetbekdi, chat_id: 1419276848
```

Напишите боту в Telegram — если отвечает, всё работает.

Railway может показать «no ports detected» — это нормально. Бот не веб-сервер, он сам ходит в Telegram, порт ему не нужен.

## Перенести существующие заказы

База сейчас лежит локально в `bot/data/bot.db`: несколько заказов и один отзыв. На Railway том создаётся пустым.

**Проще всего — начать с чистой базы.** Схема создастся сама при первом запуске. Локальный файл сохраните как архив.

Если история нужна, через Railway CLI:
```bash
npm i -g @railway/cli
railway link
railway run bash          # откроется shell в контейнере
```
и скопировать файл в `/data/bot.db`. Возни больше, чем пользы, при шести заказах.

---

## Что изменится в работе

**Правка цен.** Было: поправил `config.json` → перезапустил. Стало: поправил → `git commit` → `git push` → Railway пересоберёт сам за минуту.

**Логи.** Вместо `bot.log` — вкладка Logs в панели Railway.

**Перезапуск.** Кнопка Redeploy в панели.

**Ничего не меняется для покупателя** — тот же бот, те же экраны.

---

## Если что-то не работает

| Симптом | Причина |
|---|---|
| В логах `409 Conflict` | Локальный бот всё ещё запущен. Убейте его |
| `Не задана переменная окружения BOT_TOKEN` | Переменные не добавлены или деплой был до их добавления — нажмите Redeploy |
| Заказы пропали после деплоя | Не подключён том, либо `DB_PATH` не `/data/bot.db` |
| Бот не отвечает | Смотрите Logs: там будет причина |

## Стоит ли вообще

Честно: тот же результат даёт обычный VPS за €4–5 в месяц или Oracle Cloud бесплатно, и там правка цен остаётся «поправил файл и перезапустил», без git-push на каждое изменение.

Railway удобнее в настройке — деплой в три клика, не нужен ssh. За это платят ценой и тем, что каждое изменение конфига становится коммитом.

Для первого месяца, пока проверяете спрос, это нормальный выбор.
