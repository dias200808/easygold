# EasyGold — бот продажи голды Standoff 2

Telegram-бот с ручной выдачей. Покупатель оформляет заказ сам, вы получаете уведомление с кнопками, выдаёте голду вне системы и жмёте «Выполнено» — покупателю уходит подтверждение.

Зависимость одна — `grammy`. База на встроенном в Node `node:sqlite`, компилировать нечего, Docker не нужен.

**Требуется:** Node.js 22.5 или новее (`node -v`).

---

## Быстрый старт

### 1. Создать бота

Всё про @BotFather — в отдельном файле [BOTFATHER.md](BOTFATHER.md): готовые тексты описания, команды, юзернеймы. Оттуда нужен токен вида `8123456789:AAF...`

### 2. Установить

```bash
cd bot
npm install
cp .env.example .env
```

### 3. Заполнить `.env`

| Переменная | Что писать |
|---|---|
| `BOT_TOKEN` | токен от BotFather |
| `ADMIN_USERNAME` | ваш юзернейм **без собаки**, например `dastan` |
| `ADMIN_CHAT_ID` | можно оставить пустым |
| `DB_PATH` | `./data/bot.db`, менять не нужно |
| `MAX_ORDERS_PER_HOUR` | лимит заказов с одного человека, по умолчанию 5 |

### 4. Запустить

```bash
npm start
```

В консоли появится `Бот запущен.`

### 5. Привязать себя как оператора — обязательный шаг

Напишите своему боту `/start` с того аккаунта, чей юзернейм указан в `ADMIN_USERNAME`. Бот ответит «✅ Вы привязаны как оператор».

> **Почему без этого не работает.** Telegram не позволяет боту написать человеку первым — нужен числовой `chat_id`, а он появляется только после того, как вы сами написали боту. Пока вы не привязались, заказы будут создаваться, но уведомления уйдут только в консоль с пометкой `[!] Оператор не привязан`.

### 6. Проверить весь путь

Со **второго аккаунта** (не с админского) пройдите покупку целиком: выбор → ID → повтор ID → подтверждение → «Я оплатил». Убедитесь, что заказ пришёл вам с кнопками и что «Выполнено» отправляет покупателю подтверждение.

## Настройка `config.json`

Цены, реквизиты и тексты живут здесь. Код трогать не нужно, после правки — перезапуск бота.

### `brand`
```json
"brand": { "name": "EasyGold", "support": "@ваш_юзернейм" }
```
Название и контакт поддержки. Название используется в приветствии — если меняете, поправьте и `texts.welcome`.

### `game`
| Поле | Значение |
|---|---|
| `title` | название игры в сообщениях |
| `id_label` | как называть идентификатор («игровой ID») |
| `id_regex` | маска проверки. По умолчанию `^[0-9]{6,12}$` — от 6 до 12 цифр. **Проверьте на реальных ID Standoff 2** и поправьте, если формат другой |
| `id_hint` | подсказка, где найти ID |

### `channels` — способы оплаты
Каждый блок — отдельная кнопка на первом экране.

| Поле | Значение |
|---|---|
| `id` | внутренний код, менять не нужно |
| `title` | текст кнопки |
| `currency` / `symbol` | валюта и знак; цены берутся из `items.price` по этому коду |
| `notify_on_create` | `true` — уведомить вас сразу при создании заказа, не дожидаясь «Я оплатил». Нужно там, где реквизиты вы присылаете вручную |
| `instructions` | текст с реквизитами. Плейсхолдеры `{price}` и `{order_no}` подставляются автоматически |

**Обязательно замените** в канале `kz` номер Kaspi и имя получателя на настоящие.

Ненужный канал можно просто удалить из массива — например, если не работаете с Россией.

### `items` — номиналы
| Поле | Значение |
|---|---|
| `price` | ваша цена по каждой валюте |
| `reference_price` | цена в игре. Показывается зачёркнутой рядом с вашей — это главный аргумент витрины |
| `popular` | `true` — звёздочка на кнопке |

**Цены в примере — заглушка.** Пересчитайте от реальной закупки. Ориентиры по рынку и вилка маржи — в `../docs/РЫНОК.md`.

### `working_hours`
```json
"working_hours": { "from": 10, "to": 1, "timezone_note": "Астана" }
```
Вне интервала бот честно предупреждает, что выдача будет утром, но заказ принимает. Время считается по Астане (UTC+5).

## Как это работает

**Покупатель:**

```
/start
  ↓  Откуда оплата?   [🇰🇿 Казахстан — Kaspi]  [🇷🇺 Россия]
  ↓  Номиналы:  500 голды — 3 090 ₸  (в игре 3 390 ₸)
  ↓  Пришлите игровой ID              ← проверка по маске
  ↓  Повторите ID                     ← защита от опечатки
  ↓  Проверьте заказ    [✅ Оформить]
  ↓  Реквизиты + номер заказа   [💸 Я оплатил]
  ↓  ✅ Заказ выполнен
```

**Вам приходит:**

```
💸 ОПЛАТА ЗАЯВЛЕНА — проверьте поступление

Заказ SO2-0042
Товар: 500 голды — Standoff 2
Игровой ID: 123456789        ← тап копирует
Сумма: 3 090 ₸
Оплата: 🇰🇿 Казахстан — Kaspi
Статус: оплата заявлена
Покупатель: @nickname
Источник: tiktok

[🔧 В работе]  [✅ Выполнено]  [❌ Отклонить]
```

Проверяете поступление в Kaspi по номеру заказа в комментарии → выдаёте голду → «Выполнено».

**Команды оператора:** `/orders` — открытые заказы с кнопками, `/stats` — за сутки, за 7 дней и разбивка по источникам, `/whoami` — ваш chat_id.

```
https://t.me/EasyGoldKZ_bot?start=tiktok
https://t.me/EasyGoldKZ_bot?start=insta
https://t.me/EasyGoldKZ_bot?start=blogger1
```

Метка запоминается **при первом заходе** и не перезаписывается — то есть считается тот канал, который реально привёл человека, а не последний. Она видна в карточке заказа и в `/stats`.

Раздавайте разные метки разным блогерам — через неделю будет видно, кто приводит покупателей, а кто просмотры.

## Чтобы бот не падал

`npm start` живёт, пока открыт терминал. Для постоянной работы:

**pm2 — проще всего**
```bash
npm install -g pm2
cd bot
pm2 start npm --name easygold -- start
pm2 save
pm2 logs easygold      # смотреть логи
pm2 restart easygold   # после правки config.json
```

**systemd — правильнее на сервере.** Файл `/etc/systemd/system/easygold.service`:
```ini
[Unit]
Description=EasyGold bot
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/easygold/bot
ExecStart=/usr/bin/node --env-file=.env src/index.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```
```bash
sudo systemctl enable --now easygold
sudo journalctl -u easygold -f
```

> **Одновременно должен работать только один экземпляр.** Если запустить бота дважды (например, на ноутбуке и на сервере), Telegram начнёт отдавать ошибку 409 и сообщения будут теряться.

## Если что-то не работает

| Симптом | Причина |
|---|---|
| Заказы не приходят, в консоли `[!] Оператор не привязан` | Не сделан шаг 5. Напишите боту `/start` с админского аккаунта |
| `Не задана переменная окружения BOT_TOKEN` | Нет файла `.env` или он пустой |
| Ошибка 409 в логах | Запущено два экземпляра бота. Остановите лишний |
| Бот не отвечает вообще | Неверный токен, либо нет интернета, либо процесс не запущен |
| «Не похоже на игровой ID» на верном ID | Поправьте `game.id_regex` в `config.json` |
| Кнопки оператора пишут «Недоступно» | Нажимаете не с того аккаунта, что привязан. Проверьте `/whoami` |
| Изменил цены — не применилось | Перезапустите бота, конфиг читается при старте |

Логи всех ошибок идут в консоль. База лежит в `data/bot.db` — её можно открыть любым SQLite-браузером и посмотреть таблицы `orders` и `order_events`.

## Безопасность

- `.env` и `data/` уже в `.gitignore`. **Токен в git не коммитить** — утёкший токен означает, что чужой человек управляет вашим ботом.
- **Пароль от игрового аккаунта не спрашивается нигде.** Не добавляйте это поле никогда: на этом строится ваше отличие от LootBar и продавцов с OLX, и это же защищает покупателя от бана.
- **Кнопка «Я оплатил» не подтверждает оплату** — она ставит только статус «оплата заявлена». Деньги проверяете вы глазами в Kaspi. Нажатие покупателем никогда не должно означать поступление денег.
- Переходы статусов только вперёд. Двойное нажатие кнопки, откат `выдано → ждём оплату`, повторное «Выполнено» — всё блокируется на уровне базы.
- Каждая смена статуса пишется в `order_events`. При споре «я платил» это единственное доказательство.
- Лимит заказов с одного человека — `MAX_ORDERS_PER_HOUR` в `.env`.

## Что дальше

По порядку важности:

1. **Оформить ИП.** Приём выручки на личную карту Kaspi запрещён самим Kaspi и попадает под автоматический мониторинг КГД. Регистрация — один день и бесплатно, и она разблокирует счёт Kaspi Pay и Kaspi Кассу с чеками. Подробно в `../docs/ОПЛАТА-И-СТАТУС.md`.
2. **Фискальный чек** — обязателен по закону РК с первой продажи.
3. **Автоматическая оплата** — ссылка Kaspi с зафиксированной суммой плюс вебхук. Тогда статус `paid` ставит банк, а не кнопка. См. `../docs/ПЛАН.md`.
4. **Проверка ника до оплаты** вместо повтора ID — лучшая фишка продукта, её нет ни у одного конкурента. Нужен поставщик с валидацией по игровому ID.
5. **Второй оператор** — тогда понадобится назначение заказа и защита от одновременного взятия.
